## 2. 为什么"未达标"是结构性的（非调参可解决）

当前评测 = **无条件先验 + 随机噪声图占位 + 自回归无逐帧对齐**，三个限制都来自评测方式而非模型参数：

| # | 硬伤 | 机制 | 源码证据 |
|---|------|------|----------|
| 1 | 无条件先验模式 | ckpt 中 `game_mapping_cfg: null`，模型未注入 Elden Ring 游戏条件，输出的是"游戏无关"的通用动作先验 | T2.1 第 0 步实测；`inference_session.py` 走 else 分支，`input()` 不触发 |
| 2 | 无逐帧对应 | `predict()` 自回归把上帧输出喂回动作历史，模型生成"自己采样的轨迹"，与标注帧不存在逐帧对齐 → 逐帧 Pearson r 理论预期≈0 | `inference_session.py:210-211` |
| 3 | 无视觉输入 | 本地数据集仅含手柄标注（无图像帧），占位图为随机噪声，视觉条件不携带游戏信息 | `actions_raw.parquet` 19 列 + metadata 仅含 Twitch URL |

**推论**：在上述评测方式下，r≈0.4 在数学上不可达——0.4 需要"预测轨迹与标注轨迹逐帧同向变化"，而无条件先验 + 自回归采样轨迹与标注完全独立。这不是模型差，是"生成模型 × 判别式逐帧评测"的范式错配。

## 3. 合规性分析（MVP 原文如何支持本口径）

- **MVP 第 3 条**："报告按键准确率、摇杆**均方误差或相关系数**"——"或"字明确二选一，**主报 MSE 完全合规**，r 降为参考列在措辞上留有空间；
- **MVP 第 4 条**："zero-shot 基线：按键准确率 50%，摇杆相关系数 0.4"——基线是**对比门槛**，要求的动作是"对比并报告"，未达基线本身是合法实验结果，不是流程错误；
- 因此完成情况对照表中，MVP 第 3 条标 **✅ 完成**（指标已产出），第 4 条标 **🔶 完成（指标未达标，原因已说明）**——"如实报告未达标 + 原因"优于"含糊带过"。

## 4. 归档与汇报措辞（可直接使用）

### 4.1 指标表口径（metrics.csv / 报告表格）
- 达标判定列写法：按键列写"**达标但劣于全零基线（0.90 < 0.92），弃用裸准确率，以 precision/recall 为准**"；r 列写"**未达标（结构性原因，见 2）**"；MSE 列写"**主报指标，优于随机但劣于均值基线**"；
- 所有数字一律附带基线列（全零/均值），杜绝"裸报 90%"。

### 4.2 大报告"实验结果与分析"段落骨架（约 800 字）
1. **指标总览**：按上表呈现，先给达标判定，再给基线；
2. **按键解读**：类别失衡（真实按键率 7.97%）→ 裸准确率虚高 → precision/recall 揭示"模型几乎不按键"（recall 0.026~0.030）；
3. **摇杆解读**：MSE 主报（0.29~0.31，对比全零 0.2644 / 均值 0.1150），r 仅参考；分轴分析 j_left_y/j_right_y 暴露"无移动先验"；
4. **原因分析**：3 条硬伤（表 2），明确"评测范式错配，非模型参数问题，无调参路径"；
5. **局限性讨论**：无视觉、无游戏条件、自回归不对齐对结论的影响；给出"若要达到 r≈0.4 需注入游戏条件 + 逐帧对齐评测，超出当前数据与 MVP 范围"的边界说明。

### 4.3 验收/答辩口头表述（三句话版）
> "M3 评测已完整跑通并重复验证。按键准确率 90% 是类别失衡虚高——真实按键只有 8%，永不按键基线 92% 反而更高，所以主报 precision/recall，模型 recall 仅 3%。摇杆相关系数 0.005~0.019 未达 0.4，但这是评测方式决定的：当前是无条件先验、无逐帧对齐的自回归评测，逐帧 Pearson 在结构上不可能到 0.4；因此按 MVP 原文主报 MSE，r 作参考列，并在报告中如实说明了这一结构性原因。"
