## 二、关键技术决策（第 2 天报告核心内容）

### 决策 1：推理入口方案 → serve.py + ModelClient（ZeroMQ）

**理由**：
- 官方 `serve.py` 已实现模型加载、game conditioning、推理缓冲管理
- `ModelClient` 提供了干净的 `predict(image)` 接口，支持 `reset()` 和 `info()`
- 避免重写 `InferenceSession` 的复杂逻辑（tokenizer + flow matching + autocast）

**代价**：需要同时开两个终端（服务端 + 客户端脚本）

### 决策 2：M3 评测定位 → 游戏条件先验评测（v3 修订）

**原方案（v2）**：占位图 + 游戏条件 = "zero-shot 视觉评测"，摇杆目标相关系数 0.4。

**源码核查发现的两个硬问题**：
1. **自回归采样无逐帧对应**：`predict()` 每次结果 append 进 `action_buffer` 作为下一帧的动作历史（inference_session.py:210-211），模型生成的是"自己采样的轨迹"，与标注帧之间没有逐帧对齐 → 逐帧 Pearson r 预期在 0 附近，**0.4 不可能靠占位图达成**。
2. **game_mapping 前提未验证**：`get_game_mapping()` 用 `pl.read_parquet(src_files)` 构建映射，路径被替换成本地仓库根目录（inference_session.py:59-63）；若仓库内无该 parquet → 服务启动即崩；若 `game_mapping_cfg=None` → 无条件模式，无游戏条件。**T2.1 第 0 步已实测：`game_mapping_cfg: null` → 无条件模式确认，`input()` 不触发（R6/R3 解除）。**

**修订后方案**：
1. 评测定位为 **"游戏条件先验评测"**（若 T2.1 确认无条件模式，则措辞降级为"无条件先验评测"）
2. 摇杆**主报 MSE**（MVP 原文允许"均方误差或相关系数"），相关系数仅作参考列
3. 按键准确率保持 50% 基线对比
4. 报告明确说明评测方式的局限性（无视觉输入、自回归无逐帧对齐）

### 决策 3：可视化库 → matplotlib

**理由**：离线导出 PNG，无需浏览器；M2 分析已用 matplotlib，代码风格统一。
