# 选题七：通用游戏智能体（腾讯 IEG 课题）

## 一、课题基本信息

- **课题名称**：通用游戏智能体（腾讯 IEG 课题）
- **组数上限**：4 组
- **参考项目**：https://nitrogen.minedojo.org/ （NitroGen）
- **参考代码**：https://github.com/MineDojo/NitroGen
- **约束**：不得下载 full-data 全库；不得下载数据集全库。

---

## 二、数据与模型

- **数据集**：nvidia/NitroGen 数据集（Parquet 手柄标注，不含视频）
- **预训练权重**：CC BY-NC 4.0

---

## 三、MVP 要求

1. 跑通官方 ng.pt 推理，README 可复现
2. 下载同一款游戏 500 帧标注，统计按键与摇杆分布，可视化 10 条序列
3. 测试集 200 帧，报告按键准确率、摇杆均方误差或相关系数
4. zero-shot 基线：按键准确率 50%，摇杆相关系数 0.4
5. 第 5 天演示模型输出与标注对比（表格或录屏）
6. 归档代码、指标表、3000 字以上实验报告

## 四、立项扩展（任选一条，写入立项书）

| 方向 | 指标 |
|------|------|
| 微调 | 1 款游戏 1 小时数据：微调后按键准确率 +10 个百分点 |
| 数据过滤 | IDLE/无效帧过滤：误触发按键率 −20%，或数据量 −30% 且准确率不降 |

## 六、实践过程要求

### 人工智能辅助开发

- 课程以人工智能辅助软件工程为主方法
- 学生须在立项、设计、编码、联调、文档各阶段主动运用智能工具，同时履行人工审查职责

1. **范围控制**：立项确定的 MVP 范围贯穿全程，后续开发与变更不得擅自扩大
2. **提问方式**：每次向工具提出单一、具体的问题，说明项目背景、技术栈、困难点与期望输出；避免笼统要求"生成整个系统"
3. **审查合并**：代码合并前须有人通读改动，检查无关依赖、硬编码配置、接口不一致及明显安全隐患；第 4 天起建议组内交叉审查
4. **联调记录**：集成出现问题时，须整理现象、预期结果、报错信息与已尝试步骤，写入当日联调记录后再寻求协助

### 独立完成与双人组

- 课程以培养全栈能力为目标，鼓励独立完成；若合作，至多两人

1. 独立完成者一人承担需求、实现、测试与演示，自建远程 Git 仓库
2. 双人组共用远程 Git 仓库，两人均须有可辨识的提交记录；分工不得导致一方无法讲清系统主路径
3. 指定一名联络人与教师沟通（独立完成者即本人）
4. 自第 3 天起维护项目备忘，记录技术选型、接口约定及待解决问题

### 阶段性成果

- 每天成果写入当日报告
- 第 5 天报告应含可复现的演示说明
- 第 8 天报告应含他人可跟做的启动说明与对照立项的自测表
- 第 9 天以结课大报告收束

## 七、过程报告要求

### 第 1~8 天（小报告）

- 通用栏目：基本信息、今日目标、今日完成、当日主题必写块、自检、问题与明日计划
- 每日提交一份，按当日栏目书写

| 天 | 主题要点 |
|----|----------|
| 第 1 天 | 必做/不做、主路径与验收说法、风险 |
| 第 2 天 | 组成部分、与需求对应、选型比较 |
| 第 3 天 | 主路径数据/对象、成功与失败约定、临时假实现 |
| 第 4 天 | 启动说明、目录职责、审查纪要 |
| 第 5 天 | 演示步骤与预期现象、差距清单 |
| 第 6 天 | 两块完成说明与自测 |
| 第 7 天 | 通检表、问题与处理、遗留 |
| 第 8 天 | 回归、审查自检、他人启动、自测对照表 |

### 第 9 天（结课大报告）

- 建议 2000 字以上，覆盖：
  1. 课题背景与目标，必做与不做最终版
  2. 完成情况对照表（必做逐条：完成 / 部分完成 / 未做）
  3. 方案与实现概要、主路径说明
  4. 测试与演示说明
  5. 分工与贡献、问题回顾与改进、总结
